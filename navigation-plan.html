2. Breakpoint evidence

Method and widths tested: I built the narrow layout first, then temporarily set the links to a row and widened the viewport in Edge DevTools device mode at 320, 500, 600, 700, 750, and 900px.

First content failure: At 320px, labels split onto several lines and How It Works and Get Support ran off the edge. From 500 to about 706px, every two-word label still split onto two lines. At about 750px all six labels fit on one line, with little room left.

Chosen breakpoint in relative units: 48rem (768px). It is just above where the links first fit, which gives them a little extra room.

Long-label and zoom retest: With "Get Support and Answers from Our Team," the menu wrapped neatly at 320px, but at 800px every label split onto two lines. I added flex-wrap: wrap and white-space: nowrap in the media query so whole links move to a new row instead. At 200% zoom the page switched to the narrow layout and stayed readable.

5. JavaScript code defense

When the page first loads, the code uses querySelector to find the Menu button and the list of links. It saves them as button and list so it knows what to work with. Next, it adds the "js" class to let CSS know JavaScript is working. Then button.hidden = false makes the Menu button visible, and list.dataset.open = "false" makes sure the menu starts closed on smaller screens. If JavaScript doesn't work, the Menu button stays hidden and all the links stay visible so people are still able to use the website.

The setMenu function is what opens and closes the menu. It changes aria-expanded so screen readers know whether the menu is open or closed. It also changes data-open, which CSS uses to show or hide the links. Both are included in the same function to make sure what people see on the screen matches what screen readers announce.

When someone clicks the Menu button, the click event tells the code to run setMenu. It uses getAttribute("aria-expanded") to check if the menu is already open. If the value isn't "true", it opens the menu, and if it is "true", it closes it. This is called a toggle because it switches between two states. Enter and Space work the same way because I used a regular HTML <button>, which already supports those keyboard controls.

Lastly, when someone presses Escape, the keydown event checks if event.key === "Escape" and whether the menu is open. If both are true, setMenu(false) closes the menu, and button.focus() moves the keyboard focus back to the Menu button. This helps people using a keyboard keep track of where they are on the page instead of getting stuck on a link that's no longer visible.
